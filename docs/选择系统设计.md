# 选择系统设计（choose）

> 状态：设计结论，已与项目讨论确认；实现按分阶段落地。
> 关联：`docs/TODO.md` #11/#12。

## 1. 目标与边界

`choose` 不是“出牌阶段专用逻辑”，而是一组**选择原语 + 一次可回溯的选择会话**。

外部边界：一次可回溯的选择（`SelectionSession`）。

- 一个会话包含有序选择步骤；
- 每步回答后可返回上一步重新选择；
- 只有确认后，结果才交给执行方；choose 只做决策、不执行牌。

内部边界：

- 原语：原子问题；
- 组合：有序步骤 + 步骤间依赖；
- 颗粒度：一个原语 = 用户一次性回答的整体。

## 2. 原语

选择引擎只提供一个通用原语：

```ts
interface SelectionOption { id; label; group?; data?; }
interface SelectionStep {
  id; prompt?;
  options: SelectionOption[];
  validate: (selected) => boolean;  // 数量 + 跨选约束
  ai: (ctx) => string[];            // 完整 AI，工厂注入
}
```

旧的“选牌 / 选目标 / 布尔 / 任意选项 / 动作”不再作为引擎里的 kind，
而是收敛为规则层的工厂：

- `handCardsStep`：从手牌选牌；
- `targetsStep`：从候选角色选目标；
- `yesNoStep`：两个固定选项；
- `optionStep`：任意选项；
- `actionStep`：动作选择（出牌 / 技能 / 转化）。

`min/max/allowEmpty` 等数量约束统一进 `validate`；
AI 默认行为作为 `ai` 一起由工厂注入。

“选非手牌”不是独立原语：过河拆桥 / 顺手牵羊 / 反馈的选牌就是 `cards`，候选集来自目标区域。

## 3. 组合方式

- 步骤序列；
- 后续步骤的候选可依赖前序答案（例如选牌后按 `targetFilter` 算目标）；
- 回溯：返回上一步，清空后续答案，并重新计算后续步骤；
- 确认：返回结构化选择结果，执行方据此执行；
- 转化牌：动作 → 选源牌 → 派生 `UsedCard` → 按效果牌规则继续（如选目标）。
- AI：每个步骤自带 `ai`（工厂注入），会话不实现领域选择策略。

会话边界：一次会话覆盖“动作 + 后续可回溯选择”。出牌之后的某些后续选择
（例如过河拆桥再选一张目标区域牌）属于牌效果 `content` 的一部分，不在会话内，
不可回溯到“还没出这张牌”之前。

## 4. 需求映射

| 需求 | 会话结构 |
|---|---|
| 普通出牌 | `action(选牌)` → `targets(按牌算)` |
| 发动技能 | `action(选技能)` → 技能自己的步骤（制衡：`cards`；仁德：`cards` → `targets`） |
| 转化牌 | `action(选武圣)` → `cards(选红牌)` → 派生虚拟杀 → `targets(按杀算)` |
| 非出牌阶段出牌（响应） | `action(选闪/桃/无懈或放弃)` → 按牌算后续步骤 |
| 非出牌阶段单内容 | `action(选鬼才/突袭/离间)` → `cards` 或 `targets` |
| 流离 | `action(流离)` → `cards(弃一张)` → `targets(新目标)` |
| 特殊内容 | `cards(区域牌)` / `boolean` / `option(花色等)` |

普通出牌的步骤不固定为“选牌 → 选目标”：过河拆桥在会话内是
`action(过河拆桥)` → `targets`，之后的“目标区域选一张”在 `content` 内执行。

## 5. 颗粒度决策

- 出牌阶段的牌和技能：**一个 `actionStep`**。它们是同一个互斥决策点的混合候选列表；
  card / skill / conversion 只是候选的元数据（label、group、priority），不是独立选择步骤。
- 业炎选 4 花色：**一个 `handCardsStep`**（4 张、花色互异约束在 `validate`），不是四个步骤。
  四张牌是一次提交的整体，约束跨牌，回溯时允许任意修改其中一张。
- 仁德 / 流离：多个原语（`cards` + `targets`），因为“选牌”和“选目标”性质不同、可独立回溯。

## 6. 与现有代码的关系

- 现有 `ask` 家族（`askForCard` / `askFromAreas` / `askForTargets` / `askYesNo`）是原语雏形，
  需要泛化为候选集形式，并新增 `cards`（多选）原语。
- `chooseCardAndTargets` 是出牌阶段编排，将改为会话中的一个动作。
- 主动技能的 `content` 将逐步拆为 `select` / `execute`。
- 转化牌通过 `CardOption` / `UsedCard` 进入动作候选。
- 选择结果先不做强类型，统一 `Record<stepId, string[]>`（选项 id），等真实用例出现后再类型化。

## 7. 分阶段实施

1. `SelectionSession` + 原语；
2. 动作选择统一（牌 + 技能）；
3. 技能 `content` → `select/execute`；
4. 转化牌提供器（武圣 / 奇袭）；
5. 响应窗口复用同一会话（倾国 / 急救 / 八卦阵等）。

## 8. 暂缓 / 不做

- 通用选择 DSL；
- 真人/前端注入接口（当前 AI 默认写死，接入点留注释）；
- 观星 / 业炎等复杂步骤在真实用例出现后再定结构化描述。
- 选择结果的强类型（等有例子后再定）。

## 9. 已确认的细节决策

- `action` 通过 `actionStep` 工厂表达（不再作为引擎里的独立 kind）。
- 出牌阶段的选择与牌的后续步骤分离：会话只负责可回溯的“动作 + 选择”，
  过河拆桥再选一张区域牌这类步骤留在 `content` 里，不能回溯到出牌之前。
- 选择结果先不做强类型，统一用 `Record<stepId, string[]>`。
- 响应窗口可以注入动作选择：调用方传入动作候选，choose 不感知阶段。

> `options + validate + ai`；`min/max/allowEmpty` 收进 `validate`，
> AI 默认行为由工厂注入。
