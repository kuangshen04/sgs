# ADR-0007 决策与 AI 分层：规则可选集 / 选择原语 / 用牌窗口

状态：已落地（阶段 2 决策层重构 + 阶段 3）
落地位置：`src/decision/selection.ts`、`choose.ts`、`useWindow.ts`、`playChoices.ts`、`responses.ts`

## 背景与问题

参照无名杀（选择条件裸挂事件、UI 与规则状态混在一起、AI 靠给 `event.result` 赋 `"ai"` 字符串接管）
与 FreeKill（通用 Request 窗口 + 33 个业务 askTo\* 工厂，且按技能长出专属 askTo）的经验，
本项目定下两条：**规则层与 AI 层语义分离**、**决策与执行分离**（ask 只决策，不执行牌）。

## 决策

1. **选择是一等模型**（`selection.ts`）：`SelectionOption / Step / Plan / Session`。
   - 一个 Step 自带：`options`、`validate`、`prompt`、**`ai`（默认作答）**；
   - `SelectionPlan.nextStep(answers)` 按前序答案决定下一步 ⇒ 步骤**可组合、可依赖、可回溯**，
     不需要无名杀那种 backup/restore；
   - `runSelection(plan, game, player)` 跑完一次会话，产出 `answers`。
2. **规则可选集与 AI 判断分家**（`choose.ts`）：
   - 规则层：`computeCardOptions`（canUse）、`computeTargetOptions`（targetFilter + 距离/免疫 +
     延时锦囊的"可放置"限制）、`askFromAreas` 等**只算合法集**；
   - AI 层：`shouldUse` / 步骤的 `ai` 默认作答 / `usePriority`；
   - 二者在窗口层相遇（下条）。
3. **窗口 = 动作候选 + continuation**：
   - `useWindow.chooseUseAction` 统一"给候选 → 选一个 → 走它的选择计划"；
   - `playChoices.buildPlayActions` 组装出牌阶段候选 = 普通牌（规则合法 ∩ AI 愿意 ∩ 有合法目标）
     + 主动技能（`collectActiveEffects`）+ 转化牌（`collectConversionEffects`）；
   - `responses.buildResponseActions`/`executeResponse` 组装响应候选 = 真牌 + 响应型效果 + 放弃，
     并执行选中的动作（`useCard` / `playUsedCard` / `effect.resolve`）。
4. **AI 三层红线**（写死，注释标注注入点）：
   1. 规则层：`canUse` / `targetFilter` / 常驻效果；
   2. 窗口层：`ai.shouldUse`、候选优先级（`usePriority`/`priority`）、步骤 `ai` 默认作答；
   3. 效果层：效果内部的取舍（如目标选择顺序）。
   真人/前端接入时**只替换第 2、3 层的决策函数**，规则层不动。
5. **规则层查询统一带 `game`**：`CardDef.canUse/targetFilter(game, …)`、`distanceTo/attackRange(game, …)`、
   `effectRegistry.sum/has(game, player, key)`——因为规则要读 UC（ADR-0003），不能只靠 `player`。
6. **同优先级/多候选的排序询问**：`askOption`（ADR-0005 的触发排序即用它）；
   `askForTargets(0..max)` 供"可加目标"类效果使用（方天画戟）。

## 影响与后果

- 技能专属选择 = 各技能的 `selectionPlan`，不在 `decision/` 里长业务工厂（FreeKill 的反面）。
- 决策与执行分离的实际约束：ask 家族**不得**移动牌 / 使用牌；打出与使用一律由调用方
  （`playFromHand`→已并入 `playUsedCard`、`useCard`、`useVirtualCard`）负责。
- 代价：`decision/` 依赖 `content/`（读卡牌定义）与 `position/`（读 UC、查询区域），
  属于"规则查询层"，不是纯决策层。
