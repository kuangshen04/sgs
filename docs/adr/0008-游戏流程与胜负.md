# ADR-0008 游戏流程与胜负：轮 / 回合 / 阶段 / 判定 / 濒死死亡

状态：已落地（阶段 0 收尾 + 阶段 3 各内容项）
落地位置：`src/flow/gameFlow.ts`（结构）、`life.ts`（伤害/濒死/死亡）、`distance.ts`、`respond.ts`

## 背景与问题

流程本身不需要复杂建模，但**边界时点**必须齐全（技能挂在准备/判定/结束阶段），且"回合中死亡"
这类中断必须能把剩余阶段与轮次安全收场。

## 决策

1. **流程 = 边界事件工厂**：`runGame → round → turn → preparePhase / judgePhase / drawPhase /
   playPhase / discardPhase / endPhase`。每个工厂的 content **硬编码**，不暴露 body 参数——
   阶段是时点，不是可插拔流程。`turn` 每阶段之间检查 `player.alive`，死亡即跳过剩余阶段。
2. **回合开始重置瞬时标记**：`skipPlayPhase` / `skipDiscardPhase`（乐不思蜀、克己）。
3. **判定阶段读 UC**：按判定区 UC 的 `seq`（进入顺序）逐个结算；每张延时牌
   `moveUsedCard(uc → processing)` → 判定前无懈窗口（遗留 targeting 窗口）→ `judge()` →
   `delayContent(game, player, judgeCard|null, uc)`（`null` = 被抵消、无判定牌）→ `settleUsedCard`。
   - **判定牌不是 UC**（ADR-0003 判据）：`judge()` 是"亮出牌堆顶一张实体牌"（经处理区），
     天妒从处理区拿、鬼才替换牌同样只是实体牌；
   - 被抵消时**不 continue**，而是把 `null` 交给 `delayContent` 自行决定收尾——闪电据此按规则集
     "把收尾置入弃牌堆改为移向下家判定区"。
4. **伤害与生死**（`life.ts`）：`damage` / `recover` / `loseHp` / `dying` / `die` 都是事件；
   `GameOverError` 用于"整局结束"这类必须中断全部调用栈的语义，由入口统一捕获。
   伤害事件带 `source` 与 `card`（造成伤害的牌 = 那条 UC；技能伤害无 `card`）——
   奸雄/刚烈之类"因果归属"靠这个字段，不靠 `getParent` 推断（ADR-0001）。
5. **距离**（`distance.ts`）：座位距离 + 目标防御修正 − 来源进攻修正，最低 1；
   攻击范围取武器 `range`（无武器为 1）。两者都带 `game`（常驻效果的归属要读 UC）。
6. **胜负**：`GameState.victoryCheck`（默认 `lastManStanding`）在死亡结算后判定，
   写入 `gameOver` / `winner`。
7. **响应流程**（`respond.ts`）：杀→闪、决斗→杀、南蛮→杀、万箭→闪、求桃、无懈都走同一响应窗口
   （`ResponseRequest` + `buildResponseActions` + `executeResponse`）；"需要几张"走常驻查询
   （`shaRequired` / `juedouShaRequired`），"不可响应"由内容层读 `disresponsive`（ADR-0006）。

## 影响与后果

- 技能挂点齐全：准备阶段（洛神/观星）、判定阶段（鬼才/天妒/铁骑式判定）、结束阶段（闭月）等。
- 死亡安全：回合内死亡会跳过剩余阶段；`die`/`dying` 的处理集中在 `life.ts`，规则代码不用重复判断。
- 判定阶段仍保留一个 targeting 形式的无懈窗口（遗留分支）——它的语义是"抵消延时牌本次生效"，
  等需要时随延时锦囊一起收（见 `../TODO.md`）。
