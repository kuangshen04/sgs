# ADR-0001 事件系统：生命周期 / 栈 / 历史 / 因果 / 收尾

状态：已落地（阶段 1；收尾钩子 `onClear` 于阶段 3-U3 补入）
落地位置：`src/events/`（`GameEvent.ts` / `TriggerSystem.ts` / `history.ts` / `types.ts`）

## 背景与问题

规则文本里几乎每句"当……时/后"都要求其他技能可干预。若把"摸牌""造成伤害"写成普通函数，
技能就没有挂点；若每个动作都散着问一遍技能，又会把流程切碎。参照无名杀/FreeKill 的经验
（见 `../经验与红线.md`），选择"**给可干预的动作建事件，给不可干预的写函数**"。

## 决策

1. **事件 = 可干预的动作**。判断标准是"是否可能被技能打断/改写"：`damage` / `recover` / `draw` /
   `die` / `dying` / `judge` / `targeting` / `useCard` / `cardEffect` / `cardMove` / `shaCancelled`
   是事件；`round` / `turn` / 各阶段（`preparePhase` … `endPhase`）是**边界事件**（只做时点标记）。
   工具函数（距离、可选项计算）不是事件。
2. **`GameEvent` 生命周期固定三段**：
   `execute(content, opts?)` = 入史赋 id → `${type}.before` 触发 → `content` → `${type}.after` 触发；
   `finally` 里执行收尾 → 定稿 `endId` → 弹栈。
   - 只能在 `created` 阶段执行一次；构造与执行必须在同一事件栈上下文（防"延迟执行"导致的因果错绑）。
   - `opts.triggers: false` = 内容自行编排 before/after（`targeting`、`judge` 用它，便于在
     `cancelled` 时跳过 after）。
   - content / 收尾抛错时，`endId` 与栈仍正确收场，异常向上传播。
3. **因果 = 事件栈 + `getParent(type)`**。事件在构造时绑定栈顶为父事件；`getParent` 向上找最近同名事件
   （如无懈找它响应的那次 `cardEffect`）。不引入 `cause` 之类的外挂字段——父子关系已经表达了因果，
   且"刚烈反击伤害被误归给原杀"这类问题由"显式在事件数据上写 `card`"解决（见 ADR-0006 的伤害来源）。
4. **历史 = `game.history` 数组 + `id`/`endId` 时间戳法**：`id` == 入史下标；`endId` 在 `finally` 定稿为本事件
   子树的最后一个后代。子树在数组中连续，是时间戳法正确性的前提（严格栈纪律）。
   范围查询走 `findEventSince(game, boundary, predicate)`（"本回合是否使用过杀"等）。
5. **收尾钩子两个入口**，语义相同（`finally` 内、`endId` 定稿与弹栈之前、异常路径也执行）：
   - `execute(content, { clear })`：**创建时**声明，用于事件自身的资源/状态收尾；
   - `event.onClear(fn)`：**执行期**由触发效果登记，用于"临时状态活到本事件结束"
     （青釭剑"直到此【杀】被抵消或造成伤害"即挂在此；事件完成后登记会抛错）。
6. **触发不产生子事件**：触发过程不进历史（无名杀每 trigger 一个 arrangeTrigger 子事件的噪音教训）。
   "谁发动了技能"属于决策日志，不属于事件历史。
7. **订阅 = `TriggerSystem`**：`on(name, handler)` / `off` / `trigger(name, event)`，**随局隔离**
   （挂在 `game.triggerSystem`，不是模块级单例）。时点命名 = `${事件类型}.before|after`。

## 影响与后果

- 技能/装备效果只需声明 `timing`，无需关心事件如何被构造；新增时点 = 新增事件类型或复用既有 before/after。
- `endId` 让"某事件子树内发生过什么"可被精确查询，是克己/连营这类历史型技能的基础。
- 代价：任何新动作都要想清楚"是不是事件、before/after 放哪"，以及 content 里不能有"只写正常路径"的假设
  （取消/抛错都要能收场）。

## 不采纳 / 延后

- 事件结果收据与 `modify/transfer` 协议（数值改写的统一通道）：等真实用例；目前技能直接改 `event.data`
  或调用引擎函数。
- 中断语义（`cancelled` 之外的"整段跳过/回滚"）：目前只有 `cancelled`（targeting/cardEffect）与
  `GameOverError`（整局结束）两种。
- 事件历史的裁剪/活窗口：历史 append-only、不裁剪（见 `../TODO.md`）。
