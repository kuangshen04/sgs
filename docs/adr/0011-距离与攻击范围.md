# ADR-0011 Range：距离与攻击范围规则模块

- **状态**：边界已定，迁移待做（见 `../TODO.md` a4）
- **当前落地**：`src/flow/distance.ts`、`src/effects/persistentEffects.ts`、
  `src/content/cards/equipment.ts`；目标归位为独立 `src/range/` 模块

## 背景与问题

距离与攻击范围当前散落在三个所有者中：`flow/distance.ts` 计算座位距离和实际距离，装备/技能以
`PersistentEffect` 提供马匹与马术修正，武器范围却作为 `CardDef.range` 存放并由距离函数反查。
这使 UC 规则定义知道 Range 模块的字段，也让同一种“当前生效的规则贡献”走两套存储与归属路径。

Range 是第一个可供其它规则依赖、但 UC 基础系统本身不必依赖的规则模块。它同时也是后续
“技能使用次数”等模块的打样：先明确模块自己的问题、公开查询和贡献语义；出现第二个完整用例后，
再提炼通用模块生命周期或 DI 注册协议。

## 决策

### 1. 距离与攻击范围属于同一个 Range 模块

Range 拥有以下最终查询：

```ts
interface RangeRules {
  distanceBetween(game: Game, from: Player, to: Player): number;
  attackRange(game: Game, player: Player): number;
  inAttackRange(game: Game, from: Player, to: Player): boolean;
}
```

`seatDistance` 是本模块的纯算法，可导出供测试或其它座次规则复用，但不是内容合法性的入口。

Range **不负责**哪些牌需要距离、目标是否免疫、能否使用牌、如何选目标，也不执行装备或用牌。
【杀】调用 `inAttackRange`，【顺手牵羊】调用 `distanceBetween <= 1`；最终目标合法性仍归 ADR-0003
规定的 UC 合法性入口。

### 2. Range 只读取基础事实与 Effect 查询

依赖方向固定为：

```text
position / UC core ← effects ← range ← 需要距离的具体内容
```

- 座位基础值读取 `game.state.players`；
- 装备/技能当前是否归属、装备 UC 是否失效，由 Effects 按 ADR-0004 统一判断；
- Range 只查询当前归属成立的 Range 类常驻贡献，不直接读取 `UsedCardDef.tags`，不自行维护装备生命周期。

UC core、UC 规则定义协议与通用合法性模块均不反向依赖 Range。只有实际使用距离的内容依赖它。

### 3. 所有 Range 贡献统一用 PersistentEffect 表达

不建立单独的 `RangeProfile` / `RangeDefinitionRegistry`。Effect 定义本身是装配期静态对象；动态的是
它在某局当前是否归属、是否因 UC 失效而停用。因此马匹、马术与武器范围使用同一种定义和存储路径：

```ts
const RangeEffectKey = {
  DistanceFrom: 'range.distanceFrom',
  DistanceTo: 'range.distanceTo',
  AttackRange: 'range.attackRange',
} as const;
```

Range 拥有这些键、构造辅助与聚合语义；Effects 拥有定义存储、技能/装备归属和失效判断。内容必须通过
Range 提供的构造辅助注册贡献，不自行拼字符串或复制 `range - 1` 等编码细节。

### 4. 距离贡献使用带符号增量

```text
实际距离 = 座位距离
         + 来源的 DistanceFrom 贡献总和
         + 目标的 DistanceTo 贡献总和
```

结果最低为 1。典型定义：

- 赤兔 / 马术：来源 `DistanceFrom = -1`；
- 的卢：目标 `DistanceTo = +1`。

贡献值就是最终公式中的 delta，不采用“进攻距离存正数、查询时再减”的反向约定。

### 5. 武器范围也作为 Effect，按默认范围 1 的增量表达

```text
攻击范围 = max(1, 1 + AttackRange 贡献总和)
```

武器范围 `N` 注册为 `N - 1`：青釭剑范围 2 贡献 `+1`，方天画戟范围 4 贡献 `+3`。
当前一名角色只能装备一件武器，因此该表达与“武器设置基础范围 N”等价；技能增加攻击范围也能自然叠加。

若以后出现多个基础范围来源、“固定为 X”或“至少为 X”等第二种聚合语义，再把贡献扩成
`add` / `set` / `atLeast` 等显式模式；本阶段不预付这套协议。

### 6. 内容注册通过 Range 构造辅助收口

Range 提供类似以下纯构造函数：

```ts
rangeEffects.weaponRange(equipType, range);
rangeEffects.distanceFrom(delta, owner?);
rangeEffects.distanceTo(delta, owner?);
rangeEffects.attackRange(delta, owner?);
```

装备内容可再用 `registerWeapon` / `registerHorse` 之类局部辅助，一次注册 UC 定义和对应
PersistentEffect，避免漏注册；辅助属于“内容 × Range”的装配处，不进入 UC core。

`CardDef.range` 在迁移时删除。结构化显示若未来需要读取武器范围，应给 Range Effect 增加模块自有的
可读元数据，而不是把字段放回 UC 定义或另存一份重复 Profile。

### 7. 可选依赖在装配期表达，运行期不静默降级

Range 对 UC 系统是可选能力，对标准【杀】等具体内容是必需能力。依赖它的内容包/安装函数必须在
装配期声明依赖；缺失时 fail loud，不使用 `game.range?`、默认跳过距离，也不让业务代码按字符串
从 Service Locator 动态查找模块。

当前只有一个实现，先以 `src/range/` 的公开函数/对象作为契约；待阶段 5 出现第二个实现或真正的
模块替换用例，再把同一语义面接入 DI。Range ADR 不提前规定通用 `defineRuleModule` 框架。

## 影响与后果

- Range 从 `flow/` 独立，`flow` 不再拥有规则查询工具；
- 武器、马匹、马术统一享受 Effect 的归属、装备 UC 失效与即时重算语义；
- `UsedCardDef` 不再因 Range 增加模块专属字段；后续模块也不得默认向 UC/Skill 定义追加字段或塞入
  无类型 `extensions`，先判断既有机制是否已经拥有该定义的生命周期；
- Range 查询无局内自有状态，每次从座次、UC/Effect 当前状态派生；不使用模块级缓存或注册表；
- 通用 Effects 只提供贡献的存储与归属，不解释 Range key；最终公式与聚合规则始终属于 Range。

## 迁移与验收

1. `flow/distance.ts` 归位到 `src/range/`，调用方只经 Range 公共查询；
2. `CardDef.range` 删除，全部标包武器注册 `weaponRange` Effect；
3. 马匹/马术改用 namespaced、带符号的 Range key，原 `offensiveDistance` / `defensiveDistance` 消失；
4. 无武器范围为 1；武器范围、进攻马、防御马、马术及 UC 失效的现有行为保持；
5. 新增叠加测试：装备贡献 + 技能贡献按公式相加，结果最低为 1；
6. UC core / UC 定义协议 / 通用合法性模块对 `src/range/` 的 import 为 0；具体内容对 Range 的依赖显式；
7. `pnpm exec tsc --noEmit` 与 `pnpm exec vitest run` 全绿。

## 不采纳 / 延后

- **独立 RangeProfile 注册表**：与 Effect 的装备归属、失效判断重复；出现不能用 Effect 表达的静态
  Range 定义时再议。
- **`UsedCardDef.range` 或通用 `extensions.range`**：把消费者字段泄漏回 UC 定义，并会随模块增长膨胀。
- **`game.range?` + 缺失时跳过**：把装配错误变成规则静默变化。
- **现在抽象通用规则模块框架**：等 Range 与至少一个有局内状态的模块（候选为技能使用次数）落地后再提炼。
