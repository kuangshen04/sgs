## 写法约定

- 一篇 ADR 只描述**一个系统**的现状与理由，长度控制在一屏左右；实现细节指向源码，不抄代码。
- 决策被推翻时：改标题下的"状态"为 `已被 ADR-XXXX 取代`，正文保留（记录为什么当时这么定）。
- 新增系统的判据：它有自己的**不变量**或**生命周期**（否则写进 `../代码结构.md` 的"约定"即可）。
- 两类 ADR：
  - **系统说明**（0001–0009）：一个已落地系统的现状；状态写 `已落地`。
  - **判据/分层**（0010）：跨系统的约束与目标结构；状态写 `判据已生效（迁移待做）`，
    待做的搬家/重排一律记进 `../TODO.md`，不留在 ADR 里当隐形待办。
- 正文里"现状"与"目标"必须分开写：`现状实测` 一节记事实（附可复现的核对命令），
  目标结构写在决策里，两者的差距写进"迁移"表。
