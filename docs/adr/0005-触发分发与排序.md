# ADR-0005 触发分发与排序：座次主排序 / 强制先行 / 同角色选择

状态：已落地（阶段 3 第 6 项）
落地位置：`src/effects/skills.ts`（`dispatchTriggered`）；询问原语 `src/decision/choose.ts`（`askOption`）

## 背景与问题

同一时点可能有多名角色、多名技能同时可发动。标准规则（两游戏一致）：**按角色逆时针（座次）**
主排序；同角色同优先级由玩家手动选择先发动哪个。早期实现是"外层效果 × 内层座次、且固定从 0 号位开始"，
即**注册顺序 = 实际顺序**的巧合行为——红线：排序必须显式，不得依赖注册/导入顺序。

## 决策

`dispatchTriggered(event, effects)` 固定四步：

1. **座次主排序**：从**当前回合角色**（`state.currentIndex`）起，按行动顺序（逆时针）绕一圈，
   逐个存活角色处理；
2. **同一角色**：先执行**强制发动**的候选（`forced` 效果；装备/裸效果本就不询问），
   再对可选候选逐个询问；**多个候选时由该角色选择先发动哪个**
   （`askOption`，候选 + "放弃"；选择"放弃" = 本次时点该角色剩余候选不再发动）；
3. **每次询问前重新评估**归属 + 主公门槛 + 条件（前一个效果可能改变状态）；
4. **候选默认序**（AI 与将来前端的默认呈现序）= 技能效果 → 装备效果 → 裸效果，各自按定义序。

询问文案与默认行为：

- 单个候选 → `askYesNo('是否发动【X】', 默认是)`（AI 默认发动）；
- 多个候选 → `askOption('选择下一个发动的技能', [候选…, 放弃])`（AI 默认取候选序第一个、永不放弃）。

**触发不产生子事件**：整个过程不进历史（ADR-0001 红线）；"谁发动了什么"属于决策日志。

## 影响与后果

- 已声明的行为变化：① 多角色同一时点的结算顺序改为"从当前回合角色起的座次序"（原先按
  "效果注册序 × 座次"）；② 同角色多候选不再逐个问"是否发动"，而是问"先发动哪个"
  （AI 默认取第一个且不放弃 ⇒ 结果集合与原先一致，只是多了显式的排序点）。
- 触发分发的效果清单是**装载时的静态快照**，归属/门槛/条件都是运行期重算——这与 ADR-0004 的
  "归属重算免同步"配套，是技能/装备生命周期能即时生效的前提。
