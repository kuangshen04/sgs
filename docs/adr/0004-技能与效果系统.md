# ADR-0004 技能与效果：五形态 / 注册面 / 局内实例 / 归属与失效

状态：已落地（阶段 3 第 1–3、7 项；装备失效于 R3）
落地位置：`src/effects/effects.ts`（注册面 + 归属）、`skills.ts`（装载与分发）、
`persistentEffects.ts`（常驻查询）、`conversions.ts`（转化查询）、`src/content/info.ts`（规则文本）

## 背景与问题

技能不是"一条行为"，而是**元数据 + 效果集合**：同一技能在不同时机做不同事（奸雄只在自己受伤后），
装备效果又需要"随牌存在"的生命周期。参照无名杀/FreeKill：两者都把效果当一等公民、把装备效果
建模为技能。我们进一步要求：**获得/失去技能与失效要即时生效，且不需要注销/重注册 handler**。

## 决策

1. **效果 = 时点/条件/行为；五形态各自保留调用协议**，共享归属信息：
   - `triggered`：`timing` + `condition` + `run`（可 `forced`）；
   - `persistent`：`key` + `value(owner)`（查询即生效，无钩子）；
   - `activated`：`canUse` + `selectionPlan` + `execute` + `ai`；
   - `response`：`respondsTo` + `canUse` + `selectionPlan` + `resolve`（可声明 `virtualCard` = 产出零牌虚拟牌）；
   - `conversion`：`toType` + `canUse` + `selectionPlan` + `resolve`（产出 `{card: UsedCard, targets}`）。
2. **注册面只有两个入口**：`defineSkill({name, info?, meta?, effects})`（同名重复定义抛错，防缝合式注册）
   与 `registerBareEffect(effect)`（装备卡效果、未来模式效果）。effect 不需要 `info`（只有技能与卡牌需要，
   字段与 `name` 同级）。
3. **技能 = 局内实例**：`Player.skills: Map<string, SkillInstance{def, disabled}>` 是**权威**；
   `hero.skills` 只是"初始技能清单"内容数据；`createGame` 按它建实例。
   获得/失去 = `gainSkill`/`loseSkill`（实例增删），失效 = 实例上的 `disabled`（不触发生命周期钩子）。
4. **归属判定是唯一的效果生命周期开关**（`effectOwnedBy(game, effect, owner)`，每次查询重算）：
   - 技能来源 → `playerHasSkill(owner, name)`（实例存在且未失效）；
   - 装备来源 → `equippedUsedCard(game, owner, equipType)`（装备区里**未失效**的那条 UC，ADR-0003）；
   - 裸效果 → 恒真。
   由此**五形态一起**获得"即时生效"：新增/失去技能、装备进出、失效/复原都不需要动 handler。
5. **装载一次，运行期重算**：`installEffects(game)`（`createGame` 内置、幂等）按 `triggeredTimings()`
   为每个时点挂**一个** handler（静态效果快照），handler 内按角色重算归属/门槛/条件（顺序见 ADR-0005）。
   persistent/activated/response/conversion 无装载，全是查询面。
6. **三轴不混**（`auto` / `forced` / `compulsory`）：`auto` 是前端"自动发动"占位（引擎不消费）；
   `forced` 是效果级"强制发动"（不询问）；`compulsory` 是技能级"锁定技抗性"标签（目前无消费者）。
   组合语义：锁定技 = `compulsory` + 其触发效果 `forced`。
7. **规则文本 `info`**：只有技能与卡牌有，字段与 `name` 同级；数据源 = `docs/标包*.json`
   （唯一事实来源，不落副本），`defineSkill`/`cardRegistry.register` 按名字自动填充；
   测试锁"覆盖"（已注册内容缺 info 立即红）。约定见 `../代码结构.md`。

## 影响与后果

- 新增一位武将其至多两步：`defineSkill(...)` + `heroRegistry.register({skills: [...]})`；
  装备能力 = `registerBareEffect({equipType})`，无生命周期代码。
- 归属重算的代价：查询要能在**规则层任意位置**访问 `game`（见 ADR-0003 的机械代价）。
- 后果之一：装备效果默认不询问"是否发动"（`needsAsk = !!effect.skill && !effect.forced`）——
  这是"何时升级为 UC 授予技能"的判据之一。

## 不采纳 / 延后（见 `../TODO.md`）

- **技能次数机制**：目前只有出牌阶段的 `ctx.usedSkills`（按技能名，本回合一次性）与常驻查询；
  通用"每阶段/每轮/每局限 N 次"未做。
- **技能抗性消费者**：`compulsory` 已就位但没有读取方（"令其技能无效"类效果出现时再接）。
- onGain/onLose 生命周期钩子：等真实用例。
- 效果结果收据 / `modify/transfer` 协议：见 ADR-0001 的延后项。
