# 代码结构

> 一页导览：`src/` 目录职责、依赖方向、常用入口，以及两类**工程约定**（内容与数据、测试与质量闸）。
> 目录约定变更时同步更新本文件与 `AGENTS.md`；系统级决策见 `adr/`（索引 `adr/README.md`）。

## 依赖方向

- **两层边界**（`adr/0003`）：实体牌层（`Card`/`CardArea`/选择/`moveCards`）**不认识 UsedCard**；
  UsedCard 层（`usedCards.ts` + `usedCardActions.ts`）是装备槽/判定区的唯一写入者。
  两层唯一耦合 = 物理层在实体牌离开驻留区时调用 `game.usedCardHooks`。
- 依赖方向：`move.ts` ← `cardActions.ts` / `usedCardActions.ts` ← `flow/useCard.ts`（无环）。
- **`rules/` 是叶子层**：只依赖 `types`/定义契约，`position`/`effects`/`decision`/`flow`/`content` 都可引用。
- **`content/` 单向依赖引擎**（内容只提供定义与钩子，不反向被引擎模块引用）；
  只有入口 `index.ts` 与测试辅助 `test-utils.ts` 认识 `content/`（ADR-0009 验收判据 1）。
  内容不再有 import 副作用，注册一律走 `installXxxPack(container)`。
- `events/` 是最底层，不依赖其它簇；`position/` 依赖 `events/` 与 `types`。
- `effects/` 依赖 `events/`、`position/`（效果行为里会移动牌）；`decision/`、`flow/` 在两者之上。
- 入口 `index.ts` 只做组装；`game.ts` 负责一局的生命周期起点（**只持 `ruleSet` 引用**，不构造/不释放）。

## 常用入口

| 想做什么 | 看哪里 |
|---|---|
| 建一局 / 初始化步骤 | `game.ts` → `createGame(deck, heroes, { ruleSet })`（步骤见注释；阶段 4 身份场、阶段 5 rng 接入点已标） |
| 装内容 / 造容器 | `content/standardPack.ts` → `installStandardPack` / `createStandardContainer`（显式装配；ADR-0009） |
| 注册技能/效果 | `container.skills.define(...)`（= `defineSkill` 纯构造 + 注册）；裸效果走 `registerBareEffect` |
| 查定义（运行期） | `game.ruleSet.cards/skills/heroes`（只读窄接口：`get/all` + 效果查询面） |
| 本局装载效果 | 已内置在 `createGame`（`effects/skills.ts` 的 `installEffects`、`installUsedCardHooks`，均幂等） |
| 移动实体牌 | `position/cardActions.ts` → `moveCards`（唯一跨容器通道；**装备槽/判定区终点硬报错**；顶/底用 putTop/putBottom） |
| 进入/迁移/退出 UC | `position/usedCardActions.ts` → `enterUsedCard` / `moveUsedCard` / `exitUsedCard` / `settleUsedCard`（实体牌跟随） |
| 使用一张牌 | `flow/useCard.ts` → `useCard`（目标阶段 → 逐目标 cardEffect → 清理处理区；`useVirtualCard` 是技能构造"视为使用"的校验入口） |
| 打出一张牌 | `position/usedCardActions.ts` → `playUsedCard`（响应窗口；同样走处理区） |
| 查牌的位置 | `position/cardActions.ts` → `getCardArea`（集中索引） |
| 查 UC | `game.usedCards`（`ofCard` 倒查 / `at(loc)` 容器视图 / `all`） |
| 查规则文本 | `content/info.ts` → `skillInfo` / `cardInfo`（或 `Skill.info` / `CardDef.info`） |
| 玩家决策 | `decision/` 各模块（ask 家族/选择计划/用牌窗口/响应窗口） |
| 事件历史查询 | `events/history.ts` → `findEventSince` |
| 对账/调试不变量 | `position/cardAreaCheck.ts` → `verifyCardState` / `assertCardState` |

## 约定一：内容与装配

（结论来源见 `经验与红线.md` 2.8 的取舍规律：配置一旦需要引用代码或包含逻辑，代码配置全面胜出。）

- **内容定义 = TS 代码**：武将/卡牌/技能都引用效果函数，装配函数模式本身就是代码配置；
  军争/神话再临接入 = 新内容包 TS 代码 + 一个 `installXxxPack(container)`，不是 JSON 装载。
- **装配显式、运行期只读**（`adr/0009`）：注册只在装配期（容器），运行期只经 `game.ruleSet` 查询；
  没有模块级注册表、没有 import 副作用、没有隐式默认装配。
- **牌堆 = 纯数据**：`src/content/standardDeck.json`（108 张、32 种），与卡牌定义分离；
  军争牌堆接入时统一格式。理由是它无引用、规格规整、可由工具生成。
- **`docs/*.json` 的角色**：`标包卡牌/标包武将` 是**规则文本（info）的唯一事实来源**（装配期按名字查，
  见 `content/info.ts`）；`标包牌堆/军争篇*/神话再临*` 是规划与迁移参考数据，除 info 外不进运行时。
- **`info` 只有技能与卡牌有**（effect 不需要），字段与 `name` 同级（`Skill.info` / `CardDef.info`）；
  省略时由容器的 `register` 按装配期提供的数据源自动填充。
- **i18n**：单语先行，不预付多语言成本（真要时参考 FreeKill 的按包翻译表）。
- **插件内容不碰渲染层**：内容的表达面只有 label/group/prompt 这类声明式字段（见 `adr/0007`）。

## 约定二：测试与质量闸

- **测试与被测模块同目录**（`src/<cluster>/xxx.test.ts`；`content/heroes/*.test.ts` 随武将），
  **测试随内容走**：新增武将/机制必须带测试（FreeKill"技能自带测试"的精神 + typed 的形式）。
- **测试分层**（`adr/0009`）：
  - 下层模块的**单元测试不依赖上层内容**：用 `testGame({ cards, skills, heroes })` 现场注册
    测试用卡牌/技能（样板：`flow/judgePhase.test.ts`——判定阶段不需要乐不思蜀/闪电）。
  - "**内容 × 流程**"的**集成测试**单独标注并集中（如 `flow/gameFlow.test.ts` 的
    "judgePhase × 标包延时牌（集成）"、`content/*.test.ts` 走完整用牌流程的用例）。
  - 断言"标包里有什么"用 `standardRuleSet()`（共享只读 fixture）；需要干净容器用
    `createStandardContainer()`；要标包 + 合成内容用 `standardGame({ cards, skills, heroes })`。
- **两道闸门**：`pnpm exec tsc --noEmit` 干净 + `pnpm exec vitest run` 全绿；结构重构后再加一次
  `pnpm exec tsx src/index.ts` 整局冒烟（会跑完整局，覆盖交互路径）。
- **行为保持（有边界）**：重构默认保持规则语义与外部可观测行为，测试尽量机械更新；
  结构/API 级大重构可按新设计彻底改造并重写测试，但须**显式声明不兼容范围与行为变化**，
  禁止为迁就旧行为留兼容壳（见 `AGENTS.md`）。
- **对账不变量进测试**：`verifyCardState`/`assertCardState`（一牌一位置 + id 唯一 + UC 绑定）
  在涉及位置/UC 的测试里作为 sanity net 使用。
- **重演一致性测试**（阶段 6 落地回放时）：同 seed + 同选择日志双跑、比对状态一致——
  行为保持的终极自动化形态。
- **平台无关核心**：引擎不依赖 Node/DOM 专有 API（headless + "规则代码不读 DOM"红线）；
  平台差异（RNG/存储/网络/时钟）走 DI service 注入（阶段 5）。
