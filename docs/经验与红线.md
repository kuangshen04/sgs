> - **已落地的系统决策** → `adr/`（索引见 `adr/README.md`，含旧编号"演进 X.Y"对照表）
> - **还没落地的需求 / 方向 / 开放问题** → `TODO.md`

## 一、定位与基本约束（已确认）

- 支持**社区内容**（自定义可以成为玩法的一部分）→ 需要模块与插件机制。
- **隔离 = 模块隔离，不做运行时沙箱**：信任社区，不采用 JS/Lua 沙箱或受限 DSL。
- 运行形态：以**单机**为主；联机 = **P2P 连房主**，服务器（若有）只转发数据。
  **结算只发生在房主端** ⇒ 规则引擎保持单机语义，不需要分布式一致性；客机 = 纯视图 + 决策输入。
- 配套约定：启动插件机制设计时，同步修订 `AGENTS.md` 的"不提前设计注入接口"（社区内容即真实消费者）。

## 二、参照项目的经验（按主题）

### 2.1 内容生态与扩展

- **无名杀之痛：隔离性缺失**——API、版本、前后端都没有边界，内部 API 被当公共 API 用，
  核心永远无法自由重构，扩展互相踩。
- **无名杀之资产**：内置编辑器 + 热更新 + 常用技能组合免代码——低门槛是生态能长出来的根本原因。
- **FreeKill 之教训**：控制住了 API 但没有低门槛入口（内容要写 Lua），社区生态起不来。
- 推论：低门槛表达面与强隔离边界**必须兼得**，且不能走同一条无约束通道。

### 2.2 事件系统

- **无名杀**：显式历史树（`parent` + `childEvents[]` + `next`/`after`）是被 `waitNext` 调度逼出来的
  （栈不再是可靠父记录）；**没有清理钩子**（finish/cancel/neutralize/untrigger 互相纠缠，
  临时状态全靠技能自己记得清）；事件字段无隔离（UI 选择状态也挂在事件上）；`getParent` 找不到时
  返回 `{}` 假对象（静默错误源）。
- **FreeKill**：DFS 时间戳（递增 id + 完成时定稿 `end_id` + 全局数组）；四主流程按事件类型绑定；
  **clear 走独立不可中断的 ClearEvent**，顺序 = clear → 定稿 end_id → 出栈；`breakEvent` 让出
  `__breakEvent`、调度器把栈上到目标事件全部标 killed。
- 我们据此选：**时间戳法 + parent 链并存**、单 clear 钩子、触发不产生子事件（见 `adr/0001`）。

### 2.3 状态与位置

- **无名杀**：牌存在 **DOM nodelist** 里，移动必须动 DOM；反直觉的收益是"一个节点只能有一个父"
  提供了结构性唯一性；一开始没有统一移动事件 → "失去牌"类技能极难写；联机广播直接传 DOM。
- **FreeKill**：双结构（区域 id 数组 + 集中索引 `card_place`），索引是派生态、加载重建；
  `getCardsByArea` 默认返回克隆；**语义全塞进 moveCards**（skillName/moveMark/visiblePlayers/
  virtualEquip…）不推荐；**守恒假设踩坑**（实际不守恒，靠 printCard 负 id + Mark 改道 Void 兜底）。
- 我们据此选：**受控 CardArea（语义-free）+ 集中索引**（见 `adr/0002`）。

### 2.4 玩家决策与 AI

- **无名杀**：**选择零封装**（filterButton/filterCard/filterTarget 裸挂事件，`game.check` 直接操作
  DOM 的 selectable/selected）；流程固定为 button → card → target → confirm，**不可自定义顺序**；
  主动技能靠 backup/restore 旧条件，UI 状态与规则状态混在同一事件上；**AI 接管 = 把 `result`
  赋值为 `"ai"` 字符串**（规则与 AI 纠缠的实证）。
- **FreeKill**：**Request 是通用基础窗口**（command + 按玩家的 data + default_reply + timeout，
  协程 yield；n 个肯定回复提前结束，其余落 default_reply；**AI 是玩家对象上的 `player.ai`**，
  人类回复完或超时后才回答，避免抢答泄密）；AskTo\* 33 个业务封装 + 兼容层，
  但工厂随场景膨胀到"连单技能都长出专属 askTo"。
- 我们据此选：**选择模型保持 `SelectionOption/Step/Plan/Session`**（步骤可组合、可回溯，
  天然不需要 backup/restore），AI 三层红线（见 `adr/0007`）。

### 2.5 触发顺序与性能

- **性能共识**：结算运算量在两项目里都不是性能主角（远快于动画）。真正的要点只有两条：
  **(1) AI 的时间复杂度**；**(2) 结算代码不要读 DOM**——无名杀最大的性能开支就是读 DOM
  （牌是 nodelist 的直接后果）。
- **无名杀**：多数 trigger 是空的 → 用 **hookmap 让空 trigger 提前返回**；执行顺序按座次
  （doingList）；**同角色同优先级由玩家手动选择先发动哪个**（`chooseControl`）；silent/无翻译技能
  自动优先；firstDo/lastDo 不参与优先级选择。
- **FreeKill**：时点 → 技能表（skill_table）+ 该时点优先级降序表（skill_priority_table）。
- 我们据此选：**座次主排序 + 同角色多候选由角色选择**（见 `adr/0005`）；空触发提前返回
  我们已由 `triggerSystem` 按事件名分桶等价实现。

### 2.6 技能建模

- **无名杀**：先有技能再有效果 → 裸效果与聚合多效果技能实现不便（裸效果伪装成 `_` 前缀全局技能）；
  技能**裸读字段**（一个对象同时满足多个接口就能在多场景生效）；技能全静态、无实例
  （临时数据存 `player.storage`，靠 init/onremove 钩子补偿生命周期）；技能集合多通道
  （skills/additionalSkills/tempSkills/hiddenSkills/invisibleSkills/global）；发动流程分裂
  （主动技 useSkill 或 useCard 两条路径，触发技不走 useSkill，"发动技能时"时点只覆盖主动技）。
- **FreeKill**：**skill → effect 是后来拆的，代价非常大**；效果只能挂在技能上（没有裸效果）；
  技能同样全静态（`times` 写在静态对象上、失效状态 = `player.mark` 前缀匹配——定义与局内状态混淆）；
  frequency 标签膨胀到 21 个且语义互相包含；**can_trigger/can_use 无包装**（通用限制作为模板代码
  写死在每个效果里）；统一"发动技能"通道走 `room:useSkill`。
- 我们据此选：**效果是一等公民、技能是包装器**；**裸效果是真实需求**；**定义静态 + 局内实例**；
  可组合谓词（`subjectIsOwner` 这类组件）而非模板代码（见 `adr/0004`）。

### 2.7 多人 / 网络 / 回放

- **无名杀**：只有主机有完整事件树，客机只同步显示内容与选择条件、不结算；**随机数同步、断线重连、
  中途加入、双端一致性排查全部缺失**；录像 = 动画 + 时间戳记录，与选择无关。
- **FreeKill**：每房间一个服务端；Request 带 timeout（烧绳）/托管 AI/投降检测/旁观视角切换；
  移动只发 id 与可见性控制；`card_manager.serialize` 快照（数组权威、索引重建）。
- 我们据此选：客机 = 纯视图 + 决策输入（结构性保证）；**回放 = 确定性重演**（重跑引擎，
  不做快照式记录），三个前提 = 引擎确定性（RNG 种子化、禁 `Date.now`/`Math.random`）、
  配置快照 + 选择日志、版本管理。

### 2.8 数据驱动与内容边界

- **无名杀**：内容即 JS 代码，无打包、无 i18n，扩展覆盖靠 monkey-patch。
- **FreeKill**：内容全代码（`packages/<pkg>/` = init.lua + pkg/ + i18n/ + 资源 + customPages），
  按包存放的多语言 Lua 翻译表；内容散在代码里，**没有单一可导出的数据面**。
- 取舍规律（spring / eslint / blockly 的回归）：**配置一旦需要引用代码或包含逻辑，代码配置全面胜出**；
  数据文件只在"纯数据、无代码引用、需外部工具消费"时赢。据此：内容定义 = TS 代码；牌堆 = 纯数据；
  `docs/*.json` = 规划参考与规则文本来源（见 `代码结构.md` 的内容与数据约定）。

### 2.9 测试与回归

- **无名杀**：没有单元测试确实影响核心改动；但调试门槛极低（逻辑全在前端、开发者模式全局注册、
  console/断点/手动加事件），主要靠 e2e。
- **FreeKill**：Qt 调试门槛高 → 单测重要得多：C++ smoke + luaunit 单测 + **技能自带 `tests` 字段**
  （逐技能收集执行，屏蔽后端请求）+ `fake_backend`（平台假后端）。
- 我们据此选：**测试随内容走**（每武将/机制一个 `.test.ts`）、重演一致性测试（回放落地时）、
  对账不变量进测试（见 `代码结构.md` 的测试与质量闸）。

## 三、红线（写死；违反即回退）

1. **排序必须显式**：触发顺序只由"座次 + 同角色选择"决定，**不得依赖注册/导入顺序**。
2. **历史时间戳法的前提是严格栈纪律**：一旦引入"延迟执行/插队"的真实用例，必须先补显式事件树——
   在此之前时间戳法会静默失效。事件必须在构造它的同一上下文里执行。
3. **规则代码永不读 DOM / 渲染层**（headless 天然成立，写成红线防回退）。
4. **触发不产生子事件**：触发过程不进历史；"谁发动了什么"属于决策日志。
5. **规则层与 AI 层分离**：`canUse`/`targetFilter`/常驻效果是规则；`ai.shouldUse`/选牌/选目标/发动与否是 AI。
6. **决策与执行分离**：ask/choose 只做决策不执行牌；打出与使用由调用方（`useCard`/`useVirtualCard`/
   `playUsedCard`）负责。
7. **内容即代码、牌堆纯数据**：内容定义不退回 JSON；`docs/*.json` 不进运行时（规则文本 `info` 例外，
   见 `代码结构.md`）。
8. **测试随内容走 + 全量测试绿 + `tsc` 干净**；行为变化必须显式声明并机械更新测试。
9. **公共 API = service 接口集**（插件机制落地时生效）：未声明为 service 的内部函数不可注入
   ——对"内部 API 被当公共 API 用"的直接防御；配套要求**可卸载**（副作用注册带 disposer）。
10. **模型只在出现 2–3 个真实用例后抽象**；单例特判优先，禁止为将来的用例预付抽象
    （"有例子再抽象"）。
